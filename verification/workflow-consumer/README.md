# Workflow verification inputs

`CooperativeSource` is a bounded external input fixture for the separate upload-read interruption qualification. It delivers the literal22-byte UTF-8 prefix `name,quantity\npartial,`, then enters a latch-controlled blocking read. Interrupting the actual reader produces `InterruptedIOException` while preserving the flag. Closing the owned fixture also releases its wait, so failed tests have a finite cleanup path.

`CooperativeSourceContract` qualifies those fixture mechanics in platform and virtual threads, without application or framework dependencies. It proves that the reader is still blocked before interruption, receives no further bytes afterward, exits within3s, and closes its input. `Verify.workflowSourceFixture` archives the exact source, compiles it with JDK25 and requires both result markers. Its summary explicitly identifies this as fixture qualification, not application acceptance.

The application qualification is separate from both arms' five-task measurements. After the accepted new application source is frozen, the fixture will enter that application's real import boundary through its normal multipart input. The test will interrupt only after the blocking-read event, then verify a non-successful import, preserved interruption, closed source, real worker exit, and exact restoration of the staging tree and unrelated sentinel bytes. A subsequent valid import must still work. Both platform and virtual workers use the same scenario; an observer Future cancellation alone does not prove that work stopped.

The test must exercise the application-owned upload/CSV flow and runtime APIs directly, without replacing either runtime, spying on internal calls, or adding a production fault switch. It will use the approved controlled-file seam for source interruption; the full HTTP tests separately verify multipart authentication, validation, safe errors and successful CSV results. It does not claim that every socket/source supports interruption or that cancelling an HTTP client rolls back completed work.

Before interrupting, the application test must also observe a newly owned regular staged file in its request subtree whose bytes exactly equal the emitted prefix, while unrelated baseline paths and contents are unchanged. A source that blocks before resource acquisition is not sufficient. MIME probing may read ahead before output copying; qualify the event at the actual application's write stage, and do not mislabel a probe-stage barrier as proof of partial-file cleanup.

`UploadInterruptionProbe` independently qualifies this observation with the ordinary runtime's size-budget-only `SafeUpload.saveFile` path. Both thread modes produced one real22-byte partial file before interruption and removed it afterward, preserving the unrelated sentinel and closing the source. The probe's two empty request directories are owned by its test harness and retained for inspection. This is a runtime/input-fixture check; it does not establish that the application's MIME path or complete upload/CSV join has passed. It compiles against the actual ordinary jar plus Spring Web/Core dependencies, and does not load library test classes.

At this checkpoint the standalone fixture, its normal runner hook and the ordinary-upload qualification probe are implemented. The final application overlay/consumer and its additional interruption regression await the coordinator's explicit frozen-source handoff. The working benchmark applications and acceptance oracles are not inputs to this checkpoint.

# 31: 验证模板的版本升级与五类 agent 任务

**What to build:** 模板应用能够按文档独立交付，并在保留业务改动的情况下升级；固定任务展示新增业务、错误、外部调用和已有文件能力的真实使用路径。

**Blocked by:** 13 上传在探测、保存和失败时保持完整与有界；15 让 CSV 方言、流消费和电子表格导出策略可验证；25 隔离两个外部服务的配置、凭据和失败；26 让应用拥有本地化、日志与观测政策；30 在断连、进程丢失和结果清理后恢复同一命令

**Status:** draft — 待确认粒度与阻塞关系；未发布为 ready-for-agent。

**Traceability:** FR-07、FR-08、FR-09、FR-10；AC-03、AC-11、AC-12、AC-14、AC-15

## Acceptance criteria

- [ ] 模板与 runtime 版本分别记录，提供小型明确升级差异；不重新生成覆盖业务代码。
- [ ] 运行/验证/部署说明和环境变量闭合；基础验证与需要数据库/容器的验证清楚分层，不实际部署。
- [ ] 五项固定任务为冷启动、加端点、改错误、外部调用、已有上传/CSV 能力接入；同等环境记录旧/新方案完成、纠错和上下文成本。
- [ ] 汇总公共 API 与消费者迁移账本、29 包处置和旧发布线政策；各能力具体兼容证据由负责票提供，发布票最终闭合。
- [ ] 完成本票适用的共同测试完成标准 Q01–Q10；每项契约关联测试及运行结果，不适用维度说明理由；涉及旧 ADR 时先登记替代决策。

## Required scenarios

- [ ] 场景：新目录独立实例化、构建启动、五项任务的可观察产物；新增业务不改 runtime。
- [ ] 升级：上一模板样本带自定义业务改动，升级后改动保留、配置迁移明确、测试仍运行。
- [ ] 接合：认证与错误、外部 HTTP 与观测、受控上传到 CSV 解析；业务字段规则留应用。
- [ ] 证据：保存任务文本、环境、产物和纠错记录，不预填提升百分比；文档命令实际执行。

## Scope boundary

完整 documents、新 starter 和第二业务平台不在本票；复用证据不足时只保留应用内配置。

本票引用 server-facility 下一代脚手架 PRD v0.2，以及同批任务的测试策略与接合矩阵。当前是可评审草稿，不表示实现、测试执行或用户批准已经完成。

# 07: 让互斥操作获得真实保护或明确拒绝

**What to build:** 需要进程内互斥的操作在正确的锁下执行；所需实现缺席时不执行 action；长期键轮转不会永久耗尽锁能力。

**Blocked by:** None (can start immediately)

**Status:** draft — 待确认粒度与阻塞关系；未发布为 ready-for-agent。

**Traceability:** FR-02、FR-05、FR-09；AC-08、AC-09、AC-12

## Acceptance criteria

- [ ] 本地与分布式保证分名；等待与持有期限分开，旧接口先扩展替代再迁移消费者。
- [ ] 缺 bean、禁用或配置不满足必需保证时，在 action 之前失败；合法用户实现可覆盖。
- [ ] 释放、重入/非重入、owner、容量及键回收政策清楚，不将本地能力称作跨节点保证。
- [ ] 等待方超时或 Async 取消不代表 action 已终止。释放依据实际受保护操作结束与 owner 规则；仍在运行的旧 action 不能与新同键 action 同时进入。
- [ ] 完成本票适用的共同测试完成标准 Q01–Q10；每项契约关联测试及运行结果，不适用维度说明理由；涉及旧 ADR 时先登记替代决策。

## Required scenarios

- [ ] 正常/并发：同键互斥、不同键并发；高竞争回收不能生成两个同键有效锁。
- [ ] 边界：零/负/超长等待、容量边界、连续新键、重复释放/错误 owner；旧参数语义变化明确。
- [ ] 故障/接合：action 实际结束或抛错时正确释放；观察方超时与业务终止分别验证。缺实现时执行计数为零，关闭竞争与用户 bean 覆盖。
- [ ] 与票 03 接合：持锁 action 暂停，观察者超时/取消，第二个同键 action 仍被阻止；第一项真正结束后才恢复可用。不依赖提前解锁让测试结束。

## Scope boundary

不引入 Redis、跨节点租约或 fencing Adapter；旧公共删除受消费者盘点约束。

本票引用 server-facility 下一代脚手架 PRD v0.2，以及同批任务的测试策略与接合矩阵。当前是可评审草稿，不表示实现、测试执行或用户批准已经完成。

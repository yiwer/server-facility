# server-facility 下一代：测试策略与接合矩阵

日期：2026-10-03。状态：已随任务拆分确认，作为已发布本地 tickets 的测试要求；尚未实现或执行本轮新增测试。

本文件落实用户要求：底层脚手架的用例、场景、接合与极端使用情况应全面覆盖。关联 [PRD v0.2](../specs/2026-10-03-server-facility-next-prd.md) 与 [已发布任务清单](2026-10-03-server-facility-next-tickets.md)。每张功能票自带测试；最终发布票负责组合与证据闭合。

## 1. 全面覆盖的完成定义

全面覆盖是公开契约和关键失败模型可追溯，不是要求穷举无限输入、配置或线程调度。所有支持能力都要登记输入、输出、状态转换、失败、时间、资源和兼容语义；每个适用维度有测试与可观察断言。不适用项写理由，未验证项写影响及负责票，不得改称通过。

### 共同测试完成标准

每张已发布任务引用下列 Q01–Q10；这些要求随实现和验收一并执行。

| 编号 | 完成标准 |
|---|---|
| Q01 契约追踪 | 本票 FR/AC、公开入口和研究反例对应到测试及运行结果；已复现问题有回归，或有能力退出与替代验证。接口的输入、失败和资源归属变化有设计记录。 |
| Q02 正常与边界 | 验证正常、空/null 约定、默认、最小、等于上限、超过上限、非法/溢出输入；按能力覆盖 Unicode、编码、时间/Locale、重复和重入。旧 ≤0 表示无限制等语义不能暗改。 |
| Q03 真实接合 | 公开 API 的行为单测与必要的真实消费者组合均通过。事务、派发、身份、配置和流式传输不能仅用 mock 调用次数证明。 |
| Q04 故障与并发 | 在明确时点注入依赖拒绝、超时、取消、中断、I/O 失败或进程退出；屏障/事件/可控时钟复现交错，检查业务结果、状态和资源，不依赖随机 sleep。 |
| Q05 有界资源 | 登记字节、行列、并发、队列、键、连接、线程、临时空间等适用预算；成功/失败/取消后均清理或恢复到约定状态，重复使用不能持续无界增长。 |

## 2. 验证分层与执行频率

| 层次 | 入口和目标 | 何时执行 | 证据边界 |
|---|---|---|---|
| 公共行为用例 | 值类型、公开操作、格式解析、锁/缓存/限流状态和预算 | 每次相关变更 | 验证局部契约，不代表 Servlet 派发、真实事务或跨实例正确 |
| 配置/装配契约 | 现有 ApplicationContextRunner、条件类加载、用户 bean 覆盖 | 每次相关变更 | 快速穷举有限关键配置；另用真实依赖图复核，防止 test scope 掩盖缺包 |
| 模块接合 | 真实 Servlet HTTP、受控外部服务、JSON converter、文件系统、同类型数据库 | 随对应票与合入运行 | 走生产接合入口，不另造绕过真实实现的测试接口 |
| 独立消费与业务场景 | 普通发布 jar、模板应用、迁移、认证、持久化命令、重放/恢复 | 随场景票与集成门运行 | 消费者不能引用库内部测试源码；数据库使用 PostgreSQL 同类型环境 |
| 并发与进程恢复 | 多线程交错、双独立应用进程、提交点断连/退出/重启 | 随负责票运行，候选版本复验 | 两线程调用内存 Map 不能代表双进程与持久化恢复 |
| 有界极端与长稳 | 大输入、key churn、反复失败/取消、临时资源回收、有限 fuzz | 相关票先小规模确定性验证，夜间与候选扩大规模 | 事先登记持续时间、输入规模、阈值和依据；不通过耗尽宿主资源制造极端 |

快速流水线必须发现并执行预期测试引擎。已配置夜间任务失败时，不以快速流水线绿色替代；尚未配置调度时提供等价的可执行命令和候选版本执行记录，不把“计划以后跑”当证据。

涉及文件语义和构建的关键场景在 Windows/Linux 执行；运行容器内测试不等于验证宿主 Windows 的文件占用、设备名和权限。所有平台先决条件明确，缺数据库/容器/链接权限应记作未验证而非成功。高风险功能未覆盖的平台必须限定支持范围或补证据，不能静默跳过。

## 4. 极端情况的生成和断言

- **输入规模**：每个预算覆盖 N−1/N/N+1；输入流分别具有已知、未知和错误长度；超长单字段与大行数分开，避免总大小相同却漏掉不同内存风险。
- **数值与时间**：覆盖 NaN/Infinity/溢出、零/负、最早/最晚合法时间、TTL 边界、时钟冻结/回拨、DST 跳变与重叠；用受控 Clock/Ticker，不以等待自然时间提高稳定性。
- **调度与状态机**：同时开始、持有后暂停、到期后迟到完成、关闭中提交、取消与完成竞争。断言结果、效果计数及最终资源，不只断言某私有方法被调用。
- **I/O**：读一部分后失败、写一部分后失败、客户端停止读、损坏编码、截断容器、临时文件被占用、权限拒绝。失败注入保持明确所有者，不修改无关目录或占满宿主磁盘。
- **持久化**：精确控制事务开始、业务写入、receipt 写入、提交和响应前后的故障；测试从进程外终止受控实例，并通过独立连接观察数据库结果。
- **长稳**：先预热再重复成功/失败/取消，记录 heap、线程、连接、键状态、打开文件及暂存目录等适用指标；判断基于已登记预算或稳定上界，不写“内存看起来正常”。
- **性质/有界 fuzz**：解析器、规范化 fingerprint、格式/数值和状态机从固定种子生成输入；如发现失败，将最小样本提升为永久回归。模糊测试不能替代独立协议金样。
- **测试隔离**：并发端口、数据库 schema、临时目录和时区配置隔离；反序/并行运行不依赖全局手工 reset。共享外部环境故障与产品失败分别诊断，均不得伪报通过。

## 6. 发布证据包与阻断规则

票 33 收集同一最终提交、同一候选产物的结果；相关依赖或组合发生变化时复跑受影响用例。禁止把多个不一致的中间版本局部通过拼成整体通过。

证据包至少包含：版本/制品校验与依赖账本；各测试入口执行命令；需求与场景映射；正常/失败/跳过及发现差异；覆盖率与架构检查；操作系统及数据库环境；并发/进程故障报告；资源规模/时长/阈值与观测；seed 和最小失败样本；兼容及迁移说明。

未解释的安全、一致性、资源或平台支持缺口阻断发布。Flaky 测试若暂时隔离，必须有责任票、影响和恢复条件，且不能隔离发布阻断契约后宣称已覆盖。PRD 的原覆盖率门是最低要求；覆盖率绿色不覆盖掉失败场景。

本轮只定义测试要求和任务，不运行这些尚未实现的测试，也不将研究阶段的原基线测试改称目标版本证据。

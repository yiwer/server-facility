# ADR 0054: Separate runtime and owned-template lineage

Status: Accepted. Date: 2026-10-04. Extends ADR0050–0053; records the explicit development coordinates required by ADR0045–0047 and PRD D-02/D-09.

The original Boot3/Jackson2 development coordinate is `cn.code91:server-facility:0.1.0-SNAPSHOT`. The Boot4/Jackson3 implementation has public descriptor and behavior changes, so its active coordinate becomes `0.2.0-SNAPSHOT`. Historical jars and reports retain their actual coordinates and checksums. This does not publish either line, declare blanket binary compatibility or infer an old-line sunset from absent public releases.

The application remains owned source with its own Maven version. A small copied `template-origin.properties` identifies `secured-api`, revision `2026.10.0`, and the required runtime coordinate. Git commit/tree and measured jar hashes belong in delivery evidence outside the self-referential source tree. Copying remains JDK-only and refuses existing destinations; it is not a synchronization or regeneration system. All copied documentation links must resolve within the application or use explicit external URLs.

An upgrade verifies exact source lineage and owned-file preimages, applies a reviewed small patch, explicitly migrates configuration, and preserves custom business source/tests and unrelated property bytes. Modified owned targets require manual review before mutation. The real historical JDBC-budget patch demonstrates one template-only step with the same historical jar; it is not a patch to the entire current schema. Historical provenance is labelled reconstructed from Git. Real HTTP, query cancellation and packaged restart/data checks qualify that step independently of the fixed five-task old/new experience comparison.

Validation uses the previously agreed independent-copy/artifact-consumer and HTTP/database seams. Five tasks use one frozen common contract; application source and helper inputs, corrections and observable input bytes are retained. Cooperative interruption qualification belongs to the reusable upload/CSV example and is outside the common timed task cost. Full candidate gates and cross-platform CI remain required before ticket closure.

The final example is a fixed20-file overlay on a fresh template, derived from the immutable measured new source. Post-benchmark correction of total multipart part cardinality, outbound observation/body budgets and cooperative-source qualification are recorded separately from the five-task cost. The ordinary template gate remains intact; a fourth `assembly-workflow` artifact role builds the full inherited suite plus additions, enforces unchanged coverage and independently consumes its executable. The type-aware upload→CSV pipeline is separately qualified with test-scoped Tika; the HTTP import itself intentionally uses actual size plus CSV structure/business admission. No fixture source, optional test detector or coverage agent enters the executable.

Intermediate compile failures are preserved. `green-02-row-budget.log` actually failed because the edit helper used the wrong source encoding; its corrected run is explicitly listed. The first round07 run spun on a zero-length read after max-long arithmetic overflow and was stopped by terminating only its identified Surefire JVM. The controlled RED asserts a positive read request and therefore fails without waiting indefinitely. It is the executable regression evidence for this defect.

The JDK `ZipInputStream` preflight initially rejected SXSSF Zip64 output (`invalid entry size (expected 0 but got 1053 bytes)`), recorded in `diagnose-05-sxssf-input.log`. Commons Compress1.28.0 streaming ZIP traversal now handles that format; actual expanded bytes and entries are still counted before POI opens the central directory. POI's template marshaller can discard an underlying IOException; the workspace records its first I/O failure before POI logs/wraps it.

## Additional boundary and resource evidence

- `green-11-file-lifetime.log`: 11 API/file/ownership checks after `red-11-api-bounds.log` exposed default-list pre-enumeration and late XLS cap. Actual Windows NOSHARE_DELETE prevents owned-file deletion; standalone cleanup failure remains Err, and a prior output failure stays primary with cleanup suppressed. POSIX permission equivalent is implemented but not locally executed.
- `green-12-facade-refactor.log`: 47 Excel tests passed after facade/Javadoc cleanup.
- `red-13-cancel-formula.log`: two real failures (sparse-gap callbacks ignore interruption; long formula source incorrectly consumes cached-display budget). `green-13-cancel-formula.log`: 10 tests pass after per-callback cancellation and independent 8,192-unit formula cap. Source RuntimeException/Error and iterator cancellation clean the operation workspace.
- `green-14-finite-boundaries.log` initially failed because extra ZIP entries had no content type; changed the fixture to valid `.xml` entries, without product changes. `green-14-adversarial-resource.log` then failed a too-strict BIFF oracle: actual POI treats SST counts as advisory, reads bounded records and returns unchanged values. This is not a product rejection guarantee. The corrected exact-data/finite-resource oracle passed in `green-14-resource-biff-policy.log`, 14 tests. All initial logs retained.
- The resource child uses 64 MiB heap / 8 MiB direct / 2 CPUs, 180-second process deadline. It rejects a 32 MiB expanded ZIP 20 times under DEFAULT, processes forged 2,147,483,647 BIFF SST counts 20 times with exact unchanged rows, and streams 100,000 then 400,000 XLSX rows with explicit finite limits. 400,000-row compressed output is 9,501,793 bytes; 200 output/callback failures leave no temporary files. Measured baseline 13,738,552, final retained 13,321,704 bytes, threads 8→8. These are one actual sample, not an all-input SLO.
- `green-15-output-program-failures.log`: 6 ownership tests; borrowed output RuntimeException/Error preserves identity and cleans temporary files (existing behavior, no fabricated RED).

## Public contracts and limits

- Signed `notes:write` creates a workspace and creator membership atomically; signed read/write operations also require current membership keyed by workspace plus verified issuer/subject. A token's tenant claim or forged header does not grant membership. Revocation takes effect on the next operation; this is not a promise of instantaneous cancellation of an already authorized in-flight operation.
- Notes have immutable workspace-local unique slugs, titles and bodies. Duplicate slug creation returns409 without changing the existing row. GET/PUT/DELETE use both workspace and note ID; inaccessible workspaces403 and absent notes404 have safe ProblemDetail. Business values use bound parameters.
- Name/title/body limits are100/200/4096 Unicode code points, with required nonblank name/title, nonnull body, no NUL or unpaired surrogate. Slug is1–64 lowercase ASCII alphanumeric/hyphen and starts alphanumeric. Jackson limits document65536, strings16384, names128, numbers64, depth16 and tokens4096 before binding; chunked input is covered.
- Page size1–100, zero-based page and maximum offset10000 are checked before SQL, with long arithmetic. Sort is the exact `created/title/slug` mapping and `asc/desc`; all have an ID tiebreaker. Count and items share a read-only repeatable-read snapshot. Empty pages retain `{items,page,size,total}`.
- Pool defaults maximum4/minimum-idle0; acquisition1000ms, validation500ms, initialization1000ms. Driver connect2s/socket4s/cancel1s; server statement2000ms/lock500ms; JDBC query2s; transaction3s. Supported finite ranges and configuration commands are in the template README. Zero/infinite, malformed, normalized-away or conflicting settings fail startup. JDBC URL parameters cannot override these driver properties.
- Flyway uses the same controlled Hikari instance as business SQL, targets latest, validates checksums, ignores no future migrations, and requires successful V1/V2 history. Separate Flyway data sources, empty/missing migration directories, partial targets and unknown future schema cannot silently make the application ready. No automatic baseline or SQL initializer is enabled.
- Expected transient/connection/lock/statement budget failures become sanitized503 `persistence_unavailable`; other persistence faults500 `persistence_failed`. Known slug competition409 is selected by `ON CONFLICT` effect, not blanket constraint swallowing. The application forwards neither SQL nor driver cause/message into the HTTP error logger. Fresh safe errors retain correlation IDs. Stage budgets are not a total HTTP deadline, and a timeout does not prove a write had no effect. Command receipts/retry recovery remain29/30.
